# 行星气候推演台 · Planetary Climate Simulator

一个零依赖的行星气候模拟与推演程序，界面为深色「科学任务控制台」风格（低饱和配色、极少发光元素）。
中央是可旋转缩放、可叠加数据图层的 3D 星球（手写 WebGL 球体渲染器），左侧是参数面板，
右侧是实时数据面板，顶部是全局控制栏。

## 运行

### 方式一：双击 exe（推荐，无需安装 Node）

```
dist\PlanetaryClimateSim.exe
```

它会启动内置的本地服务并自动打开浏览器，弹出的小窗口显示访问地址；关闭该窗口即停止服务。
整个 `dist` 文件夹可以直接拷走到别的机器上离线运行。

重新构建 exe（使用 Windows 自带的 .NET Framework 编译器，不需要 SDK / npm / 联网）：

```powershell
powershell -ExecutionPolicy Bypass -File build\build-exe.ps1
```

命令行参数：`--port 9000`、`--no-browser`、`--console`（无窗口模式）、`--root "<项目目录>"`。

### 方式二：Node 静态服务器

ES 模块需要 HTTP 源（`file://` 会被浏览器拦截），所以用一个零依赖静态服务器：

```bash
node serve.mjs            # http://127.0.0.1:8787
node serve.mjs 9000       # 指定端口
```

然后用 Chrome / Edge / Firefox / Safari 打开提示的地址即可。不需要 `npm install`，没有任何第三方依赖。

## 数据图层与颜色条

图层条上的 **风场** 与 **洋流** 不只是标量图：它们会在球体 / 平面地图上叠加**箭头**，
箭头**方向 = 风向 / 流向**，**长度与颜色 = 速度**（与图例同一套色标），所以速度与方向能同时读出来。
每个箭头先画一圈**深色描边**再画彩色本体，因此在冰盖、沙漠、浅色色标上也能看清。
洋流箭头带**水陆足迹掩膜**：箭杆不允许越过海岸线，且只画在**水域占比 > 50 %** 的格子上，
而气候网格（3.75°）误判为陆地的浅海、群岛水域会用同一套参数化洋流补上，
因此不会出现"陆地上有箭头、洋面上却空着"的情况。
其余图层为标量叠加。

点击图例颜色条（或图例标题）会展开**颜色条编辑器**：

- **配色**：默认配色 + 9 种备选配色（冷暖对比 / 冷灰 / 暖褐 / 暮紫 / 陶土 / 灰阶 / 冰蓝 / 苔绿 / 黄绿），共 **10 种**，点一下即换；
  换色会同时更新**图例、3D 球体叠加、平面地图与地形编辑器里的气候底图**（球体叠加是一张原始数值纹理 +
  256 像素查找表，所以换色条必须重新上传那张 LUT，否则只有图例变、地图不变）；
- **数值范围**：直接键入最小 / 最大值，颜色条与渲染立即按新范围归一化；
- **自适应范围**：让该图层按当前数据实际 min/max 归一化（页面状态栏会显示「· 自适应」）；
- **恢复默认**：回到注册表里的默认范围、配色与自定义颜色条；
- **自定义颜色条…**：打开独立弹窗自己画一条色标（见下）。

### 自定义颜色条

弹窗里可以完全自定义当前图层的色标：

1. **点击色条上任意位置**即在该比例处插入一个色标（初始颜色取该处的当前颜色，所以插进去不会突然变色）；
2. 在**调色盘**（24 色）里点选颜色，或使用原生取色器微调；选中的色标会高亮，列表里也可以逐个改色或删除；
3. **连续渐变 / 阶梯变化**一键切换：前者在色标之间线性插值，后者把每个色标的颜色保持到下一个色标（适合分级/分档显示）；
4. 点「应用」后该图层的球体叠加、平面地图与图例全部换成新色标（图例里会多出一个标着「自定义」的色块），
   「恢复默认」可以随时还原。

各图层默认范围：

| 图层 | 默认范围 | 图层 | 默认范围 |
| --- | --- | --- | --- |
| 温度 | −30 … 40 °C | 气溶胶 / 尘埃 | 0 … 1 |
| 降水 | 0 … 500 mm/月 | 云量 | 0 … 100 % |
| 季节降水量 | 0 … 1500 mm/年 | 昼夜温差 | 0 … 50 K |
| 湿度 | 0 … 100 % | 季节温差 | 0 … 100 K |
| 植被覆盖率 | 0 … 100 % | 风场 | 0 … 50 m/s |
| 氧浓度 | 0 … 40 % | 洋流 | 0 … 2.5 m/s |
| 宜居度 | 0 … 1（**仅陆地**） | 河流 | 0 … 1 |
| 毒性 / 危险气体 | 0 … 1 | 海冰 | 0 … 100 % |

### 宜居度是"人类文明"指标，只算陆地

海洋不参与宜居度计算（图层与数据面板在海上恒为 0），因为它衡量的是人类定居条件。
陆地格子的评分由九项因素加权而成：

| 因素 | 权重 | 理想区间 |
| --- | --- | --- |
| 温度 | 0.19 | 288 K 附近（±18 K 高斯窗） |
| 相对湿度 | 0.13 | 58 %（±34） |
| 降水 | 0.13 | 78 mm/月（对数窗） |
| 植被覆盖率 | 0.13 | 越高越好 |
| 氧浓度 | 0.11 | 21 %（±9） |
| 毒性 / 危险气体 | 0.11 | 越低越好 |
| 气溶胶 / 尘埃 | 0.07 | 越低越好 |
| 地表气压 | 0.04 | 1 atm |
| 临近河流 | 0.09 | 本格或相邻气候格有河道（河网从地形网格投影上来） |

另外还有一组**硬性生存门槛**（温度、氧分压、气压）会直接把评分压到 0：
再宜居的加权分也救不了无法呼吸的空气。数据面板会同时给出「陆地宜居度均值」与「宜居陆地占比」。

## 中央主视图的视角控制

右上角「视角」分成两组：

| 组 | 按钮 | 效果 |
| --- | --- | --- |
| 大视图（两选一） | **3D** | 三维球体：拖动旋转、滚轮缩放、方向键转动（默认斜视：约 30°N / 0°E 朝向镜头） |
| | **平面** | 等经纬度平面投影：拖动平移、滚轮缩放、**← → 移动地图**、**↑ ↓ 切换纬度带**（配合 `Shift` 加速） |
| 复位到（仅 3D 时出现） | **赤道** | **赤道地区位于屏幕正中**，北半球在上 |
| | **北极** | **北极点位于屏幕正中**（正对自转轴俯视） |
| | **南极** | **南极点位于屏幕正中**（翻转到另一侧俯视） |

三个复位按钮都是「把该特征放到屏幕中心」的精确解，不是近似：相机在 +z 轴上，
`pitch` 表示把行星绕 x 轴转动多少，因此

```
北极点居中   pitch = 0
赤道居中     pitch = −π/2,  yaw = 经度 + π/2     （取 −π/2 而不是 +π/2，北半球才在上方）
南极点居中   pitch = π
```

例如 **赤道** 按钮就是「赤道圈与镜头轴垂直相交」，屏幕中心恰好是赤道上当前经度那一点，
上下对称地看到南北半球。拖动时俯仰角允许 ±π，所以能从北极一路转到南极而不会卡住。

切到「平面」时复位行会自动隐藏（平面视图没有朝向概念），切回 3D 再出现。
「复位视角」按钮在两种视图下都可用：3D 回到默认斜视，平面回到居中 1× 视图。
`scripts/view-check.mjs` 用真实投影矩阵逐条验证这些约定（无需浏览器）。

「显示」里新增 **亮暗面（昼夜）** 开关：关闭后整颗星球受光均匀，方便读取数据图层，
而不是欣赏昼夜明暗。另有自转动画、大气辉光、经纬网、探针标记等开关。
左上角 HUD 会显示当前网格分辨率与视角状态。

## 地形编辑

点顶部「地形编辑」（或在新建星球向导第 3 步）打开，支持：

- **两种视图**：平面地图 / 3D 星球预览，可随时切换。
- **左栏宽度可调**：按住两栏之间的分隔条左右拖动即可（双击恢复默认 300 px，宽度会记忆）。
- **鼠标语义（两种视图一致）**：左键拖动 = 涂抹绘制；`Ctrl` / `Alt` / `Shift` + 拖动 = 平移（平面）/ 旋转（3D）；
  滚轮 = 改笔刷半径；`Ctrl` + 滚轮 = 缩放。光标在地图上时画布上会画出**贴合指针的笔刷圆圈**（带中心点），
  按住 `Ctrl` / `Alt` / `Shift` 时圆圈隐藏、光标变成抓手，表示此时是移动而不是绘制。
- **3D 预览**：拖动旋转、滚轮缩放、`Ctrl` + 滚轮改笔刷半径，并且**可以直接在球面上涂抹**（自动换算经纬度）。
  3D 预览**没有昼夜明暗**（编辑地形时明暗面只会遮住一半地形），鼠标悬停在球面上时会显示**贴合球面的笔刷圆圈**。
- **悬停高度读数**：按住 `Ctrl` / `Alt` / `Shift` 时鼠标变成"手套"（此时不绘制而是平移），
  **光标旁会浮出该点的高度**（相对海平面的米数，并标明「陆上高度 / 水深」与经纬度），
  平面地图与 3D 预览都支持；松开修饰键即隐藏，右下的视图信息栏也会同步显示同一读数。
  高度是直接从地形高度场按经纬度双线性取值算出来的，和渲染的地形完全一致。
- **笔刷半径**：加长滑块 + 数值输入（已去掉旋钮，直接输入数字更精确）。
- **增高 / 降低**：**改变高度**，单位 **m**，可正可负、滑块步长 10 m，同样支持直接输入数字，
  每一笔是确定的绝对高度变化。
- **平滑 / 压平**：自动切换为「强度参数」。
- **生成参数**：板块破碎程度、海平面（全球占比）、大陆高度起伏、海平面高度都是加长滑块 + 数值输入，
  可以直接键入精确数值。
- **实时预览**：每一笔都会立刻重绘预览（高分辨率下自动降采样以保持流畅）。
- 可叠加气候图层（温度、降水等）作为半透明底图，用于比对地形与气候。
- **网格精度可调**：预设精度下拉框 + 总网格数滑块 + 数值输入，点「按此精度重新生成地形」
  即按新分辨率重建（最高 1440 × 720 ≈ 104 万格）。

## 选择预设星球时的网格数量

在下拉框里选中某个预设星球后，会先弹出「选择星球网格数量」对话框：包含预设档位按钮、长滑块、

## 陨石轰击（时间与模拟 → 陨石）

「陨石」分组可以模拟单次撞击，也可以模拟**持续一段时间**的多次轰击（撞击冬天）：

| 参数 | 说明 |
| --- | --- |
| **启用陨石轰击** | 总开关；关闭时下方参数不生效 |
| **轰击起始时间** | 自模拟起点起的第几个月开始（240 = 第 20 年） |
| **轰击结束时间** | 数量大于 1 时，各颗按时间**均匀落在「起始 → 结束」区间内**（带轻微随机抖动），用来模拟一段时间内被多颗陨石轰炸。等于起始时间时全部同时撞击；数量为 1 时本项无效 |
| **陨石重量** | 单颗平均质量（kg）。1e12 kg 级为区域性事件，1e15 kg 级造成全球性撞击冬天，1e18 kg 级接近希克苏鲁伯事件 |
| **陨石数量** | 每颗落在**星球上各自随机的不同位置**（按球面**面积**均匀抽样，极区不会被漏掉），重量按下方方差抽样 |
| **重量相对方差** | 各颗质量的相对标准差（对数正态抽样）：0 = 全部等重，1 = 相差数倍 |

触发后：每颗陨石在**自己的落点**附近接收一次**火球热脉冲**（质量越大越强，封顶 300 K），
同时向平流层注入**尘埃**。尘埃是一个**储库**：

- 每颗陨石的**质量**从它自己的撞击月份开始按约 2.2 年 e 折时间衰减
  （实测 2 年后保留 0.403 = exp(−2/2.2)），所以一段持续多年的轰击会**累积再消退**，
  而不是把全部尘埃都算在最后一次撞击上；
- 存活的**总质量**再经产生曲线换算成尘埃负荷。注意这里是先加质量、再换算，
  **不是把每颗的负荷相加**——那条曲线是对数的，逐颗相加会让 N 颗小陨石远比
  一颗等总质量的大陨石更糟（4 颗 1e15 会各自贡献 0.94 直接顶到上限 3.0，
  而一颗 4e15 只有 1.13）。先加质量可以保证"同样的总质量，怎么拆都一样"。

尘埃在衰减期内（1）抬高「气溶胶 / 尘埃」图层与数据面板的浊度读数，
（2）通过每格短波强迫**遮蔽阳光**，使全球降温数 K 到数十 K，降水随之下降；
降温期间冰盖扩张、反照率上升，形成二次反馈。
撞击形态是确定性的（按星球种子抽样），存档 / 读档与分支对比都可复现。

### 撞击动画

撞击发生时主视图上会播放一段动画（3D 球体与平面地图都有）：

- **火球闪光**：0.9 秒内衰减的径向渐变；
- **冲击波环**：约 2.4 秒从撞击点向外扩张并淡出；
- **影响范围**：以撞击点为心的虚线圆，半径按质量立方根标定
  （1e12 kg ≈ 30 km，1e15 kg ≈ 300 km 相当于希克苏鲁伯级，1e18 kg ≈ 3000 km），
  在尘埃衰减期内一直保留，旁边标注"陨石撞击 ×N · 最大影响范围 ≈ X km"；
- **多颗时每个落点都画**，所以一次轰击会同时看到多个环；
- 动画按**真实时间**播放（所以在 25× 速度下也能看清），撞击点转到星球背面时自动隐藏。

数据面板同时给出撞击点经纬度、影响范围半径、当前尘埃负荷与火球热脉冲。

## 创建新星球

向导共 4 步：基本参数 → 大气与恒星 → 地形 → 模拟设定。两种模式：

- **系统生成**：一键生成与地球相近的星球（其余参数已按地球基准填好），之后可继续微调。
- **完全手动**：逐项自行设定。

地形有三条路径，可任意组合：

1. **系统随机生成**：只需设定「板块破碎程度」（以及板块数量、起伏、目标海洋占比）。
2. **完全手动绘制**：增高 / 降低 / 平滑 / 压平四种笔刷，配合「全海洋 / 全陆地 / 海陆反转」
   先划出海陆范围再塑造地形。
3. **先生成再修改**：先生成，再用笔刷涂抹。

## 物理模型

两层（地表 + 大气柱）纬向能量平衡模型（EBM），气候网格默认 48 纬度 × 96 经度，并随地形分辨率自动提高（上限 96 × 192）：

```
地表：C_s ∂T_s/∂t = S(φ,t)·(1−α) + A + k·(T_a − T_s) − τ_eff·σ·T_s⁴
大气：C_a ∂T_a/∂t = k·(T_s − T_a) + ∇·(D·∇T_a)
```

- **S**：由真实轨道几何计算的大气顶日平均辐照度（含黄赤交角、偏心率、近日点位置）。
- **α**：地表 + 云反照率，冰—反照率正反馈在这里。云量不是全局常数：它由**逐格相对湿度与
  风场辐合**算出，因此「湿度」「风场」会通过云反照率改变行星能量收支。
- **τ_eff**：等效大气透射率，由 H₂O / CO₂ / CH₄ / N₂O / 气压决定；CO₂ 系数由 Myhre 辐射强迫
  （5.35 W/m² × ln(C/C₀)）换算而来。
- **A**：**逐格**气溶胶 / 尘埃短波强迫（负 = 遮光降温）：滑块基数 × 风场扬尘（干燥陆地起沙）
  + 陨石尘埃。气溶胶图层因此是真正的强迫场，而不是仅供观看的输出。
- **k**：地表—大气感热交换（约 100 W/m² / 30 K ≈ 3 W/m²K 量级），两项严格反对称，因此耦合强度
  不影响行星总能量收支。
- **大气层是"热管"而不是第二层灰体辐射体**：它有自己的（较薄的）热容量、承担经向热量输运，
  并在夜间/极夜把热量交回地表——这正是极夜不会把地面辐射到 100 K 的原因。
  单层灰体方案要么没有温室效应（强耦合时上下同温），要么需要物理上不合理的参数，所以没有采用。
- **经向输运**：大气用隐式三对角扩散（无条件稳定，扩散系数随「大气环流强度」缩放）；
  **海洋的热量收支由三项组成**（`src/physics/climate.js`，权重见 `OCEAN_TUNING`）：
  1. `currentHeatStep` 的**平流**：沿真实洋流场做迎风差分的反对称交换，塑造 SST 形态
     （西边界流暖、东边界流冷）；刻意取得较弱，因为本模型的热量输运主要由大气承担。
  2. `overturningHeatStep` 的**经向翻转环流**：极向热输送剖面在赤道与 60° 归零，相邻纬度带
     之间严格反对称交换（约 1.5 PW @ 强度 1）。它是"搬运"而非"制造"，全球收支不受影响。
  3. **上升流**：东边界流与赤道涌升把 275 K 的深层冷水带到表层，是模型里唯一的海洋热汇，
     且**只会降温**（不会把一个比深海更冷的表面"暖回来"）。赤道冷舌与大陆西岸冷海温由此出现。

  三项都随「洋流强度」缩放（上升流按 √强度，避免滑块顶端过于极端），所以这个滑块同时改变
  极地温度、冰盖、降水与洋流图层本身。`scripts/ocean-check.mjs` 分别量化三项的贡献，
  并验证平流+翻转不改变总热量（相对漂移 ~1e-10）、上升流只降温。
- **洋流只存在于海洋**：洋流场定义在较粗的气候网格上，而箭头画在较细的地形网格上，
  因此采样时用**地形水陆掩膜**加权——否则双线性插值会把海洋流速拖进内陆一整个气候格
  （≈4°），箭头就会出现在大陆上。`scripts/current-check.mjs` 逐点验证陆地流速恒为 0。
- **冰冻圈**：永久冰盖范围由年平均温度决定（季节平滑器按真实子步长积分），瞬时温度只调制厚度。
  冰雪覆盖的温度过渡带故意做得较宽（约 12 K 的 smoothstep）：过渡带太窄时边际冰带的局地增益会超过
  Planck 响应，行星会分叉进「雪球」分支——也就是 420 → 280 ppm 的 CO₂ 变化就足以触发雪球。
- **水循环**：克劳修斯—克拉珀龙方程给出饱和水汽压，海洋面积决定可供蒸发量，坡度决定地形抬升降水；
  降水效率的温度依赖被刻意压到低于 C-C 标度（约 4%/K，而非水汽本身的 7%/K）。
- **洋流与大气环流**（`src/physics/circulation.js`）：三圈环流（信风 / 西风 / 极地东风）给出纬向风与
  辐合带，风应力驱动的副热带涡旋、西边界流、赤道逆流与上升流给出洋流场；辐合带加强降水、
  上升流（冷海水）抑制降水，水汽平流把迎风坡与背风坡的干湿差异区分开。

### 地形对风场与洋流的作用（`updateWindField`）

纬向三圈环流只是**背景场**，真正吹在地面上的风还要经过地形的三道改造：

| 作用 | 参数化 |
| --- | --- |
| **阻挡** | 高地上空气稀薄、摩擦更大：`|V| × 1/(1+0.6·h/3200)` |
| **绕流 / 分流** | 坡度越陡，气流越贴等高线走：把风矢量在"沿等高线"与"背景风向"之间按 `min(0.75, 坡度/25)` 插值，保持原有流向 |
| **动力抬升** | `w = U·∇h` 存入 `grid.windLift`，迎风坡降水按它加强（`1 + 0.045·w`，上限 +170 %）、背风坡形成雨影（−55 %） |
| **海陆风 / 季风** | 海岸格按"吹向更暖的一侧"加一个分量（陆地比同纬度海洋暖 → 向岸风，正是季风机制） |
| **山谷风** | 高于 200 m 且比同纬度更暖的格子加一个上坡分量 |

### 洋流由风与海温共同驱动

`currentAt()` 的流向与流速不再只由纬度决定：

- **风应力（Ekman 漂移）**：表面流取局地风速的 2 %，并偏转 45°（北半球右偏、南半球左偏）——
  风速为 0 时洋流显著减弱（`scripts/current-check.mjs` 逐项验证）；
- **海温梯度（热成风）**：涡旋强度按纬度向海温梯度缩放（参考 1 K/110 km，0.45–1.8×），
  冷暖水团温差越大，同一片风场转出的涡旋越强；
- 西边界流 / 东边界流 / 赤道逆流 / 极地环流仍给出结构，但幅度受上面两项调制。

### 输出 → 气候的反馈闭环

面板上看到的输出并非单向展示，它们都回到能量与水分收支里：

| 输出 | 回到哪里 |
| --- | --- |
| 云量 `grid.cloudCover` | 逐格云反照率 → 行星反照率 |
| 气溶胶 / 尘埃 `grid.aerosol` | 逐格短波强迫（含陨石尘埃） |
| 相对湿度 `grid.humidity` | 云量、宜居度、昼夜温差 |
| 植被 / 干燥度 `vegetation` / `dryness` | 地表反照率、起沙量、降水效率 |
| 雪 / 海冰 / 陆冰 `snowCover` / `iceFrac` | 地表反照率、海平面 |
| 风速 `windSpeed` | 地表—大气交换系数、蒸发源、水汽平流、地形抬升降水 |
| 洋流 `currentSpeed` / `upwelling` | 表层热量平流、上升流冷却、降水抑制 |
| 河流 `river` | 陆地蒸发源（土壤湿度代理） |

标定结果（地球参数 + 默认地形种子 =「地球 · Earth (2024)」预设）：

| 指标 | 数值 | 指标 | 数值 |
| --- | --- | --- | --- |
| 平均地表温度（12 月均值） | **287.97 K（14.82 °C）** | 全球降水 | ~82 mm/月 |
| 行星反照率 | 0.269 | 云量 | 60 % |
| 冰盖面积 | 6.5 % | 雪盖面积 | ~5 % |
| 海平面变化 | −0.23 m | 最暖/最冷纬带 | 298.4 / 259.0 K（差 54 K） |

> 这里报的是**12 个月滑动平均**（面板与曲线里的 `平均地表温度（12 月均值）`）。
> 单月瞬时值会随季节在 ±2 K 内摆动，用瞬时值判断「是否在漂移」会被季节循环误导；
> 12 月均值才是平衡态的指标。地球实测全球均值 288.15 K，模型落在 287.98 K（差 0.2 K）。
>
> 收敛过程：第 1 年 286.88 K → 第 40 年 288.10 K → 第 60 年 287.98 K →
> 第 100 年 287.97 K → 第 150 年 287.97 K。
> 第 60–150 年的线性趋势是 **−0.00001 K/年**（90 年共 −0.001 K），即真正的不动点。
>
> 注意冰—海洋耦合会带来一个**有界的数十年振荡**：12 月均值会在 ±0.3 K 内呼吸，
> 周期约数十年。判断"有没有在漂移"要看**趋势**而不是峰谷差——所以
> `physics-check.mjs` 断言的是最小二乘斜率（< 0.005 K/年），不是波动范围。

#### 地形如何驱动风场与洋流（本次重点）

早期版本的洋流**几乎不受地形影响**：`currentAt` 把"洋盆"写在固定经度上
（lon ≈ −60 与 +150 的两个余弦波瓣，注释里叫 Atlantic-ish / Pacific-ish），
所以大陆摆在哪儿都不影响一根箭头；海岸上升流也用同一套假洋盆撒点。
风场则只看到一个局部高度梯度：没有陆面粗糙度、没有背风侧、阻塞强度也只跟高度有关。

现在两者都由**真实地形**驱动（`src/physics/coast.js` 从水陆掩膜算出离岸距离、
离岸法向、沿岸切向、陆架权重，以及向东/向西到陆地的距离），于是：

| 机制 | 实现 | 实测 |
| --- | --- | --- |
| 西边界流 | `westKm` 小 ⇒ 窄、快、**向极**，沿真实岸线切向 | 1.03 m/s，是洋盆内部的 **3.6 倍** |
| 东边界流 | `eastKm` 小 ⇒ 宽、慢、**向赤道** | 0.66 m/s，弱于西边界 |
| 沿岸射流 | 任意岸线附近沿切向的流动 | 贴岸格点 cross/along = **0.08**（外海 0.86） |
| 岸线边界条件 | 近岸压制跨岸分量 + 陆架摩擦 | 水无法流进陆地，流向被迫沿岸转向 |
| 海岸上升流 | 沿岸风应力 → Ekman 输运有离岸分量 | 风向反转即从 0.46 变 0.00 |
| 陆面粗糙度 | 陆上风速 = 海上 × 0.68 | 外海 4.9 → 陆地 2.5 m/s |
| 地形阻塞 | 无量纲山高 **N·h/U**（用**次网格峰值**，不是格点均值） | 高地 1.7 m/s（低地 3.5） |
| 阻塞的方向性 | 山脊横切来流才显著减速（`align` 因子） | 对齐度 0.55 的高地上风速 2.2 m/s |
| 背风侧 | 上风方向取一格采样：先爬升后下沉 ⇒ 风影/焚风 | 抬升格点 988 个、下沉 568 个 |
| 峡谷加速 | 两侧地形更高 ⇒ 气流被挤压加速 | — |
| 海陆风 | 逐纬度带的**陆—海温差**，随离岸距离衰减 | 暖大陆吸来向岸风 |

回归断言在 `scripts/terrain-flow-check.mjs`：**只改变海岸线几何、风速风向完全相同时，
流场平均变化 44.7%，6.5% 的箭头反向**——这正是旧版恒等于 0 的那个量。

#### 与地形无关的稳定性（重要）

同一套「2024 年地球」参数在不同地形上必须都停在温带分支——这是之前出问题的地方：
地形稍亮一点点就会一路滑进雪球分支（−45 °C 左右），看上去像"温室气体正常却越来越冷"。

原因有四个，都已修掉：

1. **极向热输送不守恒**。`transportAirStep` 过去守恒的是**未加权**的纬带和 ΣT。热量被搬到
   高纬后落进了代表面积小得多的纬带，于是 **Σ(cosφ·T) 每步都在减少**——行星在没有任何
   温室气体变化的情况下持续失能，表现为约 2 K / 40 年的稳定降温。现在按纬带面积权重守恒，
   `scripts/physics-check.mjs` 里有专门的回归断言（相对漂移 1.75e-14）。
2. **海冰面积被厚度卡住**。冰面积曾由冰厚（向平衡态松弛约 10 年）门控，于是**反照率会连续
   几十年慢慢爬升**，肉眼看上去就是"没有原因地越来越冷"。现在冰面积只由气候（年均温）决定，
   厚度只影响体积与海平面。
3. **初始温度场是辐射平衡解**，极地 90 K，头几年是在把极地"加热化开"，第一年因此虚低。
4. **标定用的是"另一个世界"**（最隐蔽的一个，见下）。

#### 标定脚本与 app 用了不同的参数（这次的真正元凶）

前三条修好之后，Node 里一切正常、浏览器里依然滑向雪球。原因是**校验脚本自己推错了参数**：
app 启动时跑 `state.js` 的 `applyAutoRules`，其中水汽规则是

```
humidity = exp((tGlobal − 288)/14) × 78 × supply      // 288 K、海洋占比≥70.8% 时正好 78
cloud    = 12 + humidity × 0.72                       // → 68.16
```

而脚本只照抄了 cloud 那一行，喂进去的却是 `defaults().humidity = 68`，于是算出
cloud = 60.96。**云量差 7 个百分点 → 行星反照率差约 0.05 → 平衡态完全不同**：
脚本认为稳态在 288 K，真实 app 却在 30 年内冻成雪球。

修法不是"再调一次参数"，而是**取消重复实现**：规则搬到 `src/state/derive.js` 的纯函数
`deriveAuto()`，app 与所有脚本共用，脚本一律通过
`appDefaultParams(defaults)` 拿初始参数。`tests/probe.html` 会在真实 app 里逐月打印
温度/反照率/冰盖，用来确认脚本世界和 app 世界一致。

| 地形 | 30 年 12 月均值温度 | 反照率 | 冰盖 |
| --- | --- | --- | --- |
| 种子 20240 @360×180（默认） | 288.19 K | 0.268 | 6.3 % |
| 种子 4242 @360×180 | 286.83 K | 0.282 | 6.7 % |
| 种子 777 @360×180 | 289.81 K | 0.261 | 3.0 % |
| 种子 12345 @360×180 | 288.92 K | 0.268 | 5.0 % |
| 种子 20240 @180×90 | 288.46 K | 0.266 | 6.0 % |
| 种子 20240 @720×360 | 281.94 K | 0.317 | 13.0 % |

**全部地形都没有出现雪球，离散度 7.9 K。**
离散度有**两个**来源，加地形耦合之后第二个变得明显了：

1. **海陆分布**改变了行星反照率与风场；
2. **网格分辨率**：地形越细，越能解析出高的次网格山峰（阻塞更强）与更清晰的冰缘，
   于是更冷。这是数值效应而非物理差异——同一颗行星在不同网格上不该差这么多，
   是目前最大的已知取舍（见文末）。

稳定性来自三处：冰雪覆盖的温度过渡带取 **24 K**（约为 244–292 K 的年均温区间），
海冰/陆雪反照率按观测取 **0.56/0.76**，过顶云反照率取 **0.27**。
过渡带越宽，冰缘每升 1 K 移动的纬度越多、冰—反照率反馈的增益越小。

> `CLOUD_ALBEDO_MAX = 0.27` 不是"一块厚云的反照率"（那是 0.4–0.5），而是让
> `albedo = surf·(1−ca) + ca` 这个公式能复现**地球短波云辐射效应**的等效值：
> 地球短波 CRE 为 −47 W/m²，即行星反照率的 0.138；模型算出的云量均值是 0.596，
> 于是 ca·(1−surf) ≈ 0.138 → ca ≈ 0.162 → 该常数 ≈ 0.27。
> 取 0.38 会让真实世界反照率升到 0.338、吸收降到 225 W/m²（地球 240），30 年冻成雪球。

实测安全边界：把 τ 再**升高约 0.02**（相当于多反射 **40 W/m²** 的阳光，约为吸收量的 16 %）
才会掉进雪球分支；而 CO₂ 从 420 减半到 210 ppm 只相当于 τ +0.011。
换句话说，温带分支可以容纳约 200–1500 ppm 的 CO₂ 而不发生失控。

气候敏感度：CO₂ 280 → 420 ppm 为 **+2.5 K**；420 → 840 ppm（加倍）为 **+3.4 K**
（地球观测估计约 3 K）。水汽反馈取 `KAPPA_H2O = 0.0032 K⁻¹`（≈1.25 W m⁻² K⁻¹），
有意低于观测的约 1.8 W m⁻² K⁻¹——这样在保持敏感度接近地球的同时，
冰—反照率失控仍留有很大的安全边界。
`scripts/physics-check.mjs` 会逐条打印并守住上面这张表。

这不是 GCM；它捕捉的是反馈结构、季节循环与长期平衡态的趋势与量级。

## 已知取舍

- 地形网格默认 360×180，可选 180×90 至 1440×720；气候网格随地形分辨率提升（上限 96×192）。
  高分辨率下绘制时预览会自动降采样，以保持笔刷响应。
- **网格分辨率会改变平衡态，这是目前最大的已知取舍**：360×180（气候 96×48）→ 288.3 K，
  720×360（气候 192×96）→ 282.5 K，差约 6 K。原因是网格越细，越能解析出高的次网格山峰
  （阻塞更强）与更清晰的冰缘（边缘冰区面积更大），而冰反照率取到观测值后又把这点差异
  放大了。**这是数值效应，不是物理差异**——同一颗行星不该因为换了网格就冷 6 K。
  想消掉它需要把冰缘与阻塞改成只对大尺度温度/地形响应（例如先做尺度平滑再判冰），
  代价是要重跑一次标定。当前选择是先保证地形耦合正确、且任何网格都不进雪球。
- **平衡温度对地形种子有约 ±4 K 的敏感度（实测离散度 7.9 K）**：海陆分布改变了行星反照率
  与风场，岛多/云多的地形更亮更冷。预设星球都有固定种子，所以同一个预设每次结果一致；
  「系统生成」的随机地形则会有几 K 的差异。
- 极地温度比地球实测偏高几 K（模型为单层灰体大气，极向热输运用一个等效涡扩散系数代替
  真实的涡动与瞬变扰动，混合得比地球更彻底）。
- 气候敏感度（CO₂ 420 → 840 ppm 平衡态）为 **+3.4 K**，与地球观测估计的约 3 K 相当。
  这是两个旋钮折中的结果：冰雪覆盖的温度过渡带取 24 K（早期版本 18 K）压低冰—反照率反馈，
  而水汽反馈取 `KAPPA_H2O = 0.0032 K⁻¹`（≈1.25 W m⁻² K⁻¹，仍低于观测的约 1.8）。
  两者都朝"离雪球分支更远"的方向留有取舍空间；如果更看重安全边界，可以调低 `KAPPA_H2O`。
- **海岸上升流现在是"局地"现象**，全球平均效应因此比以前小得多（关掉所有海洋项只降
  ~1.3 K，以前是 ~5.7 K）。旧版用固定余弦波瓣撒上升流，覆盖了每一片大洋的一大块；
  现在它只出现在**真实岸线走向 + 真实沿岸风**都合适的地方。真实上升流本来就窄（约 100 km），
  它对 417 km 网格的**全球**均值贡献小是合理的——它要的效果是区域性的
  （冷而干的东岸荒漠），这一点由 `terrain-flow-check.mjs` 直接断言。
- **行星反照率 0.269，略低于地球的 0.294**：模型的冰雪覆盖比地球少（冰盖 6.5 %，
  地球海冰 + 陆地雪盖更多），地表反照率因此偏低；云量一侧则按观测的云辐射效应取
  `CLOUD_ALBEDO_MAX = 0.27`。净效果是行星能量收支正确（吸收约 240 W/m²），
  但"亮在云上、暗在地上"的分配与地球不完全一致。
- **不要把"厚云单体反照率 0.4–0.5"直接填给 `CLOUD_ALBEDO_MAX`**：这个常数是要复现
  短波云辐射效应的等效值，见上面标定一节的推导。踩过这个坑（填 0.38），后果就是雪球。
- **海洋三项里，上升流是唯一真正的"热汇"**：平流与翻转只搬运热量（已用 `scripts/ocean-check.mjs`
  验证总热量不变），所以「洋流强度」滑块同时含有"更强的极向输运"与"更强的上升流冷却"两种效应，
  净效果是升温还是降温取决于两者与冰盖反馈的竞争。这与地球海洋的净效应方向一致，
  但**不能**把滑块简单地读成"洋流越强越暖"。
- 陆冰厚度上限 1.5 m、海冰 3 m：模型里冰是薄壳而非冰盖，因此冰量偏小，海平面变化也偏小。
- **陨石只改变气候与大气，不改地形**：撞击不会挖出陨石坑（那需要重建高度场、水陆掩膜与河网），
  火球热脉冲也只给撞击所在的气候格加一次有上限的升温，而不是把撞击动能全部注入该格。
- 箭头叠加是屏幕空间采样：球体上按画布像素间距采样再反投影，因此极区附近箭头会因投影压缩而显得更密。
- 表面反照率纹理使用 WebGL1 允许的 CLAMP_TO_EDGE + LINEAR：非 2 次幂纹理配 REPEAT 会导致
  纹理不完整并采样为纯黑，这一点在代码里有注释说明。
- exe 启动器使用 `TcpListener` 手写 HTTP 而不是 `HttpListener`：后者依赖 http.sys 内核驱动与
  URL ACL 预留，在受限环境下会抛 `PlatformNotSupportedException`，且通常需要管理员权限。
